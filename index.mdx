Broccoli Queue is an async message queue library for Rust applications — a type-safe alternative to Celery built on Tokio. It provides a unified API for publishing, consuming, and processing messages across Redis, RabbitMQ, and SurrealDB backends with configurable retry strategies, connection pooling, and fairness queues.

## Why Broccoli Queue?

If you're building async Rust applications that need reliable background job processing, Broccoli Queue gives you a clean, idiomatic API without sacrificing performance or flexibility.

## Get Started

<Steps>
  <Step title="Add the dependency">
    Add `broccoli_queue` to your `Cargo.toml` with the desired broker feature:
    ```toml Cargo.toml
    [dependencies]
    broccoli_queue = { version = "0.4.6", features = ["redis"] }
    ```
  </Step>
  <Step title="Build a queue">
    Create a `BroccoliQueue` with the builder API:
    ```rust
    use broccoli_queue::queue::BroccoliQueue;

    let queue = BroccoliQueue::builder("redis://localhost:6379")
        .pool_connections(5)
        .failed_message_retry_strategy(Default::default())
        .build()
        .await?;
    ```
  </Step>
  <Step title="Publish a message">
    Publish any `Serialize + Deserialize` type:
    ```rust
    #[derive(Clone, serde::Serialize, serde::Deserialize)]
    struct Job { id: String, task: String }

    queue.publish("jobs", None, &Job { id: "1".into(), task: "process".into() }, None).await?;
    ```
  </Step>
  <Step title="Process messages">
    Consume and handle messages with full type safety:
    ```rust
    use broccoli_queue::brokers::broker::BrokerMessage;

    queue.process_messages("jobs", Some(4), None, |msg: BrokerMessage<Job>| async move {
        println!("Processing: {:?}", msg.payload);
        Ok(())
    }).await?;
    ```
  </Step>
</Steps>

<Note>
  Broccoli Queue requires Rust with Tokio async runtime. All queue operations are `async` and return `Result<_, BroccoliError>`.
</Note>
